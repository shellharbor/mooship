## Constraints and conventions

- Existing directories and leftover Docker resources are never silently reused. `nginxproxy` is a reserved slug; the resolved path is checked against `/var/www`, and project directory symlinks are prohibited. Reinstallation requires a separate, explicit `remove.sh` invocation.
- Database, Redis, and PHP ports are published only on localhost. `.env`, `config.php`, and backup archives use mode 600; normal output does not reveal passwords. Required Moodle/SSL/proxy failures stop deployment with a nonzero exit code. Endpoints receiving secrets must use HTTPS.
- nginxproxy site configurations resolve `<slug>_nginx` per request (Docker DNS), so a stopped project cannot block the shared proxy; project nginx trusts only the `X-Forwarded-For` entry appended by nginxproxy (ADR-0003). Existing proxies keep their copy of `site-template.conf`; templates never rewrite deployed projects.
- Proxy lifecycle edits share `lib/proxy.py`, which preserves Mooship's block-list/mapping format and scopes exact resource matches to the common network list, nginxproxy mounts, and top-level network/volume declarations. Comments and blank lines do not stop list processing; removal cleans active and disabled entries; activation never enables a neighboring block. Empty collections stay valid. Deactivation applies Compose before restarting/checking nginxproxy so the disabled site's network and certificate volume detach. This editor targets Mooship-generated configurations rather than arbitrary YAML layouts.
- The Moodle Compose template quotes `{SLUG}` placeholders so dependency tooling can parse the original YAML. `configure_compose_db` accepts quoted and unquoted resource keys; generated names and native/container database behavior remain unchanged.
- Database branch contract (2026-10-15): restored the new-project template to `mysql:8.4` LTS and `postgres:17-alpine` after merged Dependabot updates selected MySQL 9.6/PostgreSQL 18. PostgreSQL 18's image changes the default data directory/volume layout, which the existing mount did not accommodate. Dependabot now ignores MySQL major/minor and PostgreSQL major updates; changes to these branches require migration/storage and backup/restore validation. Generated Compose tests assert both database images and PostgreSQL's data mount. Existing deployments and volumes are not modified by template edits; never downgrade their data directories in place.
- HTTPS is the default. `--no-ssl` serves Moodle over HTTP on port 80 through both nginx layers, sets the HTTP `wwwroot`, and saves `SITE_SCHEME=http` in `.env`. Basic Auth protects the application in either mode; ACME stays public. Restore preserves the saved protocol; older archives without `SITE_SCHEME` default to HTTPS. See README for manual HTTP-to-HTTPS migration.
- Full archive v1: `/var/backups/mooship/<slug>_<timestamp>.tar.gz`, containing the project directory, database dump, SSL data, and manifest. The application and certificate renewal pause during the snapshot; previously running services resume even on failure. Optional retention (`--keep N`) removes only `<slug>_YYYYMMDD_HHMMSS.tar.gz` archives; hooks must be root-owned and not group/other-writable; schedules are `mooship-backup-<slug>.timer` units.
- `restore.sh` accepts a trusted v1 archive created by Mooship and an unused slug matching the archive; the user must type the slug to confirm. Native databases/users must not already exist. `remove.sh` preserves backups; native DROP requires a matching `.mooship-native-database` marker, written after successful database/user creation. Older native projects without the marker retain their databases for manual review.
- Local AI-KIT container convention: new Dockerfiles, containers, and microservices must be Kubernetes-ready under the local `ai-kit/CONTAINERS.md` standard when available in the checkout. Kubernetes availability in this project must be verified separately.
- Architecture decisions: see `docs/DECISIONS.md` and `docs/adr/`.

## Open questions

- The production server, DNS, complete Moodle installation, and actual SSL issuance have not been verified.
- The six `phpXX.ini` templates keep stock values (`upload_max_filesize=2M`, `memory_limit=128M`); new projects override them with `mooship.ini`, while projects created earlier still use the stock limits.
- Redis stores Moodle sessions in new projects (sprint 2); Moodle's application cache (MUC) is not configured automatically. Compatibility of older Moodle releases with the fixed database images needs separate validation.
- Sprint 2 behavior verified only with mocks and component checks: real Moodle sessions in Redis, SMTP delivery, systemd timers, and `doctor.sh` against a live site are covered by `e2e.yml`, which has no runs on `main` as of 2026-10-15.
- The proxy lifecycle parser defects reproduced on 2026-10-06 were fixed and regression-tested on 2026-10-14. Shared nginx configuration validation still follows application/restart; deployment cleanup or recovery is not implemented.
- Hardening still pending: localhost PHP-FPM publication, `moodledata` mode 777, fixed native DB address `172.17.0.1`, and password-file input. SMTP values avoid the child `docker exec` argument list, but an explicitly supplied `--smtp-password` still appears in the original deployment command. Resource profiles tune workers/buffers without enforcing container memory or CPU budgets.
- Backups require space for a temporary project copy and the archive; older zip files are not full v1 backups.
